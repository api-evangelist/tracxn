# Tracxn

> Tracxn is a market intelligence platform for private company data — 7.7M+ companies across 2,000+ sectors and 3K+ feeds — used by VC, PE, investment banking and corporate M&A teams. Programmatic access ships as Data Solutions: the Tracxn REST API (v3.0 current, v2.2 being deprecated), an official remote MCP server, scheduled SFTP dumps, and Snowflake/BigQuery integrations. Tracxn publishes no /llms.txt on its own domains; this file was generated by API Evangelist from the catalog and from Tracxn's own published documentation — verify details against Tracxn's site. The one real llms.txt on the estate is the help centre's (see below).

## APIs
- [Tracxn API developer page](https://w.tracxn.com/api-developers-page): marketing overview of Data Solutions.
- Base URL (current): https://platform.tracxn.com/api/3.0 — v2.2 at https://platform.tracxn.com/api/2.2 is announced for deprecation.
- Uniform contract: every data endpoint is a POST taking `filter`, `sort`, `from`, `size`. No GET (405), no path or query parameters.
- Authentication: an account-scoped token in the `accessToken` request header. Tokens are environment-specific (Playground vs Production) and must not be reused across environments.
- `size` defaults to 20 AND maxes out at 20 — pagination via `from` is mandatory above 20 results.
- Billing is per ENTITY RETURNED (1 credit each), so pagination consumes credits in multiples of 20. Zero-result queries are free.
- [Official Postman workspace](https://www.postman.com/tracxnapi/tracxn-api) — the real API reference. Two public collections (TracxnAPI Production, TracxnAPI Playground) carrying the API Guide, rate limits and the response-code table. Harvested verbatim to postman/ in this repo.
- [API documentation (platform login required)](https://platform.tracxn.com/a/api/gettingstarted/apibasics)
- No OpenAPI is published anywhere. The machine-readable contract is the Postman collection.

## Endpoints (v3.0)
- POST /api/3.0/companies — company search and detail
- POST /api/3.0/fundingrounds — funding rounds (was /api/2.2/transactions)
- POST /api/3.0/acquisitions — M&A events (was /api/2.2/acquisitiontransactions)
- POST /api/3.0/ipos — IPO events (v3.0 only)
- POST /api/3.0/feeds, /api/3.0/practiceareas — the two-level sector taxonomy
- POST /api/3.0/timeseries/{revenue|netprofit|ebitda|valuation|balancesheetassets|balancesheetequity|balancesheetliability|cashflowoperatingactivity|cashflowinvestingactivity|employeecountlabourfilings|employeecountannualreport}
- POST /api/3.0/{companies|fundingrounds|investors|acquisitions}/metric — aggregation; rate-limited to 10/hour and 100/day
- POST /api/2.2/investors — investor SEARCH is still v2.2-only

## MCP
- Server URL: https://platform.tracxn.com/mcp — official, first-party, REMOTE. Nothing to install.
- Auth: OAuth 2.1, authorization_code + PKCE (S256), dynamic client registration, single `read` scope. Requires a Tracxn subscription with MCP access enabled.
- Discovery: RFC 9728 protected-resource metadata and RFC 8414 authorization-server metadata are served under /.well-known/*/mcp (saved in well-known/).
- 11 tools: load_prompts, search_companies, search_legal_entities, search_funding_rounds, search_acquisitions, search_investors, search_ipo_events, search_time_series, search_locations, search_sectors, resolve_entities.
- Metering: 1 MCP credit per result returned; status checks and zero-result queries free; monthly per-user cap typically 2K–10K.
- Clients: Claude, ChatGPT, Cursor, Gemini CLI, Perplexity, plus any MCP SDK client. API-token auth for in-house platforms is "coming soon".
- [What is Tracxn MCP?](https://help.tracxn.com/en/articles/14686877-what-is-tracxn-mcp)
- [Available data tools](https://help.tracxn.com/en/articles/15131870-available-data-tools-with-tracxn-mcp)
- [Connect any MCP client](https://help.tracxn.com/en/articles/15131843-connect-any-other-mcp-compatible-client)

## Limits and errors
- Production: 100/second, 1,000/minute, 10,000/hour, 100,000/day. Playground: 100/hour, 1,000/day. Key Metrics endpoints: 10/hour, 100/day.
- NO rate-limit response headers (no RateLimit-*, no Retry-After) — a client cannot read its remaining budget at runtime.
- Errors are a custom {errorCode, message} JSON envelope, not RFC 9457 problem+json.
- 403 + errorCode 403000000 = auth failure. 403 + "API out of credits" (application code 900) = credits exhausted, NOT retryable. 429 = rate limited. Missing data points are omitted from responses, not returned as null.

## Not available
- No webhooks and no server-side push — Tracxn states this explicitly; it is on the roadmap. Change detection is poll-only via event-date filters and the `lastUpdatedDate` field.
- No OpenAPI, no GraphQL, no A2A agent card, no status page, no public SLA, no dated changelog, no security.txt of Tracxn's own, no published security certifications.
